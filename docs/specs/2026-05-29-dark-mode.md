## Problem

The app is light-mode only. A theme toggle is a v0 nice-to-have and a straightforward addition to the monochrome design system.

## Approach

Tailwind v4 generates utilities that reference CSS custom properties (`bg-black` → `background-color: var(--color-black)`). Overriding `--color-black: #ffffff` and `--color-white: #000000` in `.dark` globally flips the monochrome palette without touching component files. Gray scale is inverted symmetrically (gray-50 ↔ gray-950, etc.) for consistent contrast on dark backgrounds.

## Implementation

- `useTheme` hook: reads/writes `githatch:theme` in `sessionStorage`, applies/removes the `dark` class on `<html>`.
- `index.css`: adds `@variant dark (&:where(.dark, .dark *))` for class-based dark mode; overrides `--color-black`, `--color-white`, and the full gray scale in `.dark`; changes body base styles to use `var(--color-black)` / `var(--color-white)` so they participate in the flip.
- `App.tsx`: consumes `useTheme`, adds a `Light` / `Dark` toggle button in the header.
- `ActivityPanel.tsx`: `Sparkline` SVG uses `currentColor` for bar fill (inherits body text color) and `var(--sparkline-empty)` for zero-height bars; variables defined in CSS.

## Persistence

`sessionStorage` — cleared when the tab closes. Theme restores on re-open as light (acceptable; no inline-script flash-of-unstyled-content mitigation needed since sessions always start fresh).

## Non-goals

- System preference (`prefers-color-scheme`) detection — explicit toggle only in v0.
- `localStorage` persistence across tabs.
- Custom accent colours — the palette remains strictly monochrome.
